# Agent Task v5 — Unified Multimodal Agent Runtime

Authoritative scope and acceptance gate: `docs/governance/VERSION_CONTROL.md#v5--unified-fast-multimodal-agent-runtime-and-research-release`

## Implementation sequence

### A. Unified DLM runtime

Create one project-controlled runtime that exposes stable internal operations:

```text
generate(request, expansion_context)
structured_read(state, spec, candidates)
```

Share model weights/process by default. Treat deeper state/context reuse as an optimization that requires correctness tests and benchmarks.

### B. Reuse experiments

Measure separately:

```text
separate services
shared process/weights
shared multimodal preprocessing
any additional safe cached-state/context reuse
```

For each optimization, report latency, memory, and decision-equivalence checks.

### C. Stable service API

Implement a project-owned decision endpoint conceptually equivalent to:

```text
POST /v1/decide
```

It accepts backend-neutral state/goal/tools/constraints/budget and returns candidates, uncertainty, controller action, trace summary, and execution result when an execution adapter is enabled.

### D. Environment/tool boundary

Keep action execution explicit and permissioned. Record result/transition so the next observation can re-enter the decision loop.

### E. Full benchmark

Run the complete matrix from `docs/research/EVALUATION.md` with:

- reference backends;
- candidate corruption;
- multimodal conditions;
- calibration;
- adaptive compute;
- latency/memory/throughput;
- risk–latency Pareto analysis.

### F. Reproducibility release

- freeze experiment configs;
- add environment/hardware metadata capture;
- validate clean local install;
- validate all doc links and source-of-truth ownership;
- retain baseline adapters rather than deleting comparison code.

## Completion rule

Do not call the research release complete merely because the endpoint runs. The milestone closes only when the acceptance gate and core evaluation reproduction are satisfied.
