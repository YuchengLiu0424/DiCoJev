# Agent Task v3 — Native Diffusion Structured Read

Authoritative scope and acceptance gate: `docs/governance/VERSION_CONTROL.md#v3--project-owned-native-diffusion-structured-read`

## Implementation sequence

### A. Runtime read primitive

Implement project-owned abstractions for:

```text
read template/canvas construction
seeded/fixed regions as supported
answer-slot positions
candidate-label token validation
read step/sample configuration
logit/logprob extraction
probability normalization
```

Do not expose engine-specific fields through public project schemas.

### B. NativeDLMDecisionBackend

Implement:

- binary candidate-set adequacy read;
- categorical candidate selection read;
- optional NOTA read within selection;
- normalized result contract;
- backend capability declaration;
- diagnostics describing runtime/read mode.

### C. Same-process integration

Use the same project-controlled model runtime/weights for generator and read when technically feasible, while keeping generation and read as logically separate operations.

### D. Compatibility

Do not remove JevCloud, DjevLocal, CrossEncoder, or Mock. They are required research comparisons.

### E. Comparative benchmark

For matched states/candidate sets, record:

```text
DjevLocal result/latency/memory
NativeDLMRead result/latency/memory
CrossEncoder result/latency/memory
```

### F. Robustness tests

- unsupported token labels;
- malformed/empty read slots;
- numerical normalization edge cases;
- repeated stochastic reads with tolerance;
- backend failures fail closed.

## Do not implement in this task

Do not yet make calibrated-score claims or introduce broad learned coverage/candidate-quality training unless needed only for benchmark plumbing.
