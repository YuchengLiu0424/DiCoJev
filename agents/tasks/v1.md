# Agent Task v1 — Real DLM and Reference Backends

Authoritative scope and acceptance gate: `docs/governance/VERSION_CONTROL.md#v1--real-dlm-generation-and-reference-backends`

## Implementation sequence

### A. DiffusionGemma generator adapter

- implement service/client abstraction for local `google/diffusiongemma-26B-A4B-it`;
- implement prompt/message builder targeting project-native `DecisionSpec`;
- pass explicit goal/tools/constraints;
- enforce candidate/generation limits;
- add timeout/cancellation;
- record generation latency and raw-output metadata;
- route model output through existing bounded harness validation.

### B. JevCloudBackend

- implement environment-only `JEV_API_KEY` loading;
- compile request via the existing Jev compiler;
- parse `noul` coverage and `choice` selection;
- normalize errors/timeouts;
- create fixture tests with no live call requirement.

### C. DjevLocalBackend

- configurable base URL/model;
- `/v1/systemone`-style request support;
- label token validation hook;
- parse coverage/choice outputs;
- preserve provider diagnostics;
- health-check/integration marker;
- report read latency separately from generator latency.

### D. CrossEncoderDecisionBackend

- implement candidate scoring interface;
- normalize selection scores;
- implement a separately named set-level coverage baseline/head/heuristic;
- record exact coverage method in result metadata.

### E. Backend switch example

Provide one text request whose generated semantic candidate set is persisted, then passed unchanged to every compatible backend selected via configuration.

### F. Tests

- fixture responses for Jev/Djev;
- provider errors and malformed distributions;
- backend capability flags;
- config-only backend swap;
- generator invalid JSON -> harness failure/repair path;
- separate latency fields.

## Do not implement in this task

Do not implement the multi-round multimodal closed loop, native project structured read, calibration training, or shared-runtime optimization.
