# Agent Task v4 — Calibration, Learned Coverage, Feedback Policy, and Adaptive Compute

Authoritative scope/gate: `docs/governance/VERSION_CONTROL.md` v4.

## A. Experiment records

Store task/state IDs, candidate set/provenance, acceptable actions/y_cov, backend raw scores, selection outcome, feedback bundle, controller action, latency/token/compute metadata, and execution outcome when available.

## B. Calibration

Implement suitable binary/categorical calibrators (e.g. temperature/logistic/isotonic), persist identity/training split/version metadata, and never overwrite raw fields.

## C. Learned coverage / independent verifier

Implement at least one learned set-adequacy estimator and one independent/decorrelated verifier condition for correlated-failure analysis.

## D. Candidate quality

Add learned/scored validity, executability, redundancy, utility features as required by experiments; keep them separate from coverage.

## E. Feedback policy experiments

- keep canonical feedback vocabulary fixed unless design docs explicitly change;
- implement learned/calibrated mapping from normalized evidence to feedback codes where appropriate;
- compare blind retry, binary retry, typed DiCoJev feedback, and long-form feedback;
- measure recovery, wrong ACT, latency, feedback tokens/bytes, and success per feedback token;
- ablate individual feedback codes.

## F. Adaptive compute

Use risk evidence plus latency/compute/token budgets; compare adaptive expansion with fixed-K generation.

## G. Reporting

Generate reliability, risk-latency, and risk-latency-token plots/tables defined in `docs/research/EVALUATION.md` from recorded run artifacts.

## Do not implement

Do not claim unified-runtime speedups until v5 shared-runtime measurements exist.
