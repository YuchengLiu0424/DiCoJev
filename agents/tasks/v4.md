# Agent Task v4 — Calibration and Adaptive Compute

Authoritative scope and acceptance gate: `docs/governance/VERSION_CONTROL.md#v4--calibration-learned-coverage-candidate-quality-adaptive-compute`

## Implementation sequence

### A. Experiment data schema

Define reproducible records containing:

```text
state/task IDs
candidate set + provenance
y_cov / acceptable actions when available
backend raw scores
selection outcome
controller action
latency/compute metadata
execution reward/outcome when available
```

### B. Calibration

Implement pluggable calibrators appropriate to binary/categorical evidence:

```text
temperature scaling
logistic/Platt-style mapping
isotonic regression
```

Persist calibrator identity, training split, metrics, and version hash. Never overwrite raw fields.

### C. Learned coverage

Implement at least one learned set-adequacy estimator and one deliberately independent/decorrelated verifier condition for correlated-failure analysis.

### D. Candidate-quality model

Add learned or scored features for validity/executability/redundancy/utility as specified by the experiments. Keep these outputs distinct from coverage.

### E. Adaptive compute policy

Implement policy input containing risk evidence plus remaining latency/compute budget. Compare adaptive generation against fixed-`K` baselines.

### F. Research baselines

Add experiment support for:

- NOTA-only rejection;
- top-1/entropy coverage proxies;
- repeated generation;
- conformal-style set/stopping baseline where data assumptions permit;
- independent versus same-backbone verifier.

### G. Reporting

Generate reproducible tables/plots defined in `docs/research/EVALUATION.md`, especially reliability and risk–latency curves.

## Do not implement in this task

Do not claim unified-runtime speedups before the shared-runtime implementation is benchmarked.
